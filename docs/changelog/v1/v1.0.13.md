# sizeofvar v1.0.13 Changelog

**Release Date**: October 2026
**Release Type**: Patch
**Branch**: `next` → `master`

---

## Overview

A dev-tooling dependency patch. Three development dependencies move to their current releases: `@cldmv/fix-headers`, which maintains the comment headers at the top of the repository's source, test, config and workflow files, from 2.1.1 to 2.2.0; `@cldmv/configs`, the package that supplies the shared fix-headers configuration, from 1.2.0 to 1.2.4; and the `@cldmv/vitest-runner` test runner from 1.2.0 to 1.5.3. No runtime code changed: `sizeofvar.js` is exactly as in v1.0.12, and the package still has no runtime dependencies.

The fix-headers bumps were made with a header restamp in mind, but neither produced any header change in this repository: running `npm run fix:headers` against this release rewrites 0 files, so the only files touched are `package.json` and `package-lock.json`, plus the documentation described below.

---

## 🔧 Dependencies

All of these are dev dependencies. The lockfile changes are limited to the packages below, the package's own version, and the one transitive package the test runner pulls in (`chalk`).

- **`@cldmv/fix-headers` `^2.1.1` → `^2.2.0`** (resolved 2.1.1 → 2.2.0; [#32](https://github.com/CLDMV/sizeofvar/pull/32) moved it to 2.1.4 and [#37](https://github.com/CLDMV/sizeofvar/pull/37) to 2.2.0). The 2.1.4 release no longer stamps a header into files that have no usable comment syntax (strict JSON such as `package.json`, and Markdown unless explicitly forced), never walks into `node_modules` or other dependency folders, and processes every repeated `--input` value instead of only the last. The 2.2.0 release changes what `@Last modified by` means: it now names whoever last edited a file's content, so a run that only rewrites a header (a date format conversion, a corrected `@Project`, new spacing) keeps the recorded editor instead of claiming the file for whoever ran the tool. The 2.1.2 and 2.1.3 releases in between were repository-maintenance releases with no change to the tool. It only runs through the `fix:headers` script; nothing that ships depends on it.
- **`@cldmv/configs` `^1.2.0` → `^1.2.4`** ([#37](https://github.com/CLDMV/sizeofvar/pull/37)). `.configs/fix-headers.json` extends `@cldmv/configs/fix-headers.json`, and from 1.2.4 that shared config sets `forceAuthorUpdate` and `forceLastModifiedAuthorUpdate` to `false` (both were `true` in 1.2.0). Together with fix-headers 2.2.0, a `fix:headers` run no longer overwrites `@Author` or `@Last modified by` on every file.
- **`@cldmv/vitest-runner` `^1.2.0` → `^1.5.3`** ([#35](https://github.com/CLDMV/sizeofvar/pull/35)), the test runner. This restores the bump from [#27](https://github.com/CLDMV/sizeofvar/pull/27), which merged into `next` just after the previous release and was dropped by the post-release reset of `next` ([CLDMV/.github#360](https://github.com/CLDMV/.github/issues/360)); it is reinstalled at the latest version instead of the original 1.5.1. The runner's own Node requirement rises from `>=20.19.0` to `>=22.12.0`, and its `chalk` dependency moves from 5.6.2 to 6.0.1 (Node 22 or later); the runner's package metadata also now declares Apache-2.0 instead of MIT. Test tooling only; nothing that ships depends on it.

## Upgrade notes

- No breaking changes, and no runtime code changed. It's a drop-in replacement for v1.0.12.
- For contributors: running the test suite now needs Node.js 22.12.0 or later, which is the floor the CI matrix has used since v1.0.9. The package itself declares no `engines`, and consumers are unaffected.
- For contributors: fix-headers 2.2.0 decides whether a file's content was edited by comparing the working tree with git `HEAD`, so run `npm run fix:headers` before committing, not after.

# sizeofvar v1.1.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/1.1.0`

---

## Overview

sizeofvar is now an ES module with a CommonJS entry. `import sizeofvar from "@cldmv/sizeofvar"` and the new named export `import { sizeofvar } from "@cldmv/sizeofvar"` load the ESM build, and `require("@cldmv/sizeofvar")` still returns the function itself. The source moves from `sizeofvar.js` at the repository root to `src/index.mjs`, tsup builds the published `dist/`, and the package ships TypeScript declarations for the first time.

The size heuristic is unchanged. Every value returns the same byte count as in v1.0.14, and the 91 characterization tests pass with only their import path changed.

This is a minor release, but two changes can break existing installs: the package now requires Node.js 22.22.0 or later (it declared no `engines` before), and deep imports such as `@cldmv/sizeofvar/sizeofvar.js` no longer resolve. See [Breaking Changes](#-breaking-changes) before upgrading.

## ✨ Features

### ESM source, CommonJS entry and tsup build ([#59](https://github.com/CLDMV/sizeofvar/pull/59), fixes [#53](https://github.com/CLDMV/sizeofvar/issues/53))

- `sizeofvar.js` moves to `src/index.mjs` (as a rename, so `git log --follow` keeps its history) and becomes an ES module with a default export and a named `sizeofvar` export. `package.json` sets `"type": "module"`.
- `src/index.cjs` is the CommonJS entry. It checks that the running Node.js can `require()` an ES module, then exports the function itself, with `.sizeofvar` and `.default` pointing at the same function. On a Node.js without `require(esm)` it throws an `ERR_REQUIRE_ESM` error that names the required version and suggests `import()` instead.
- tsup bundles `src/index.mjs` into `dist/index.mjs`, minified with names kept, and copies `src/index.cjs` verbatim to `dist/index.cjs`. The CommonJS entry loads the ESM bundle instead of carrying a second copy of the code. `prepack` runs the build, so a packed or published tarball always has a fresh `dist/`.
- `package.json` gets an `exports` map for `"."` (`types`, `import`, `require`) plus `./package.json`, and `main`, `module` and `types` point at `dist/` and `types/`. `files` limits the tarball to `dist/` (without sourcemaps) and `types/`.
- The JSDoc is type-checked, and `types/src/index.d.mts` ships a typed `sizeofvar(object: any, level?: number, from_array?: boolean): number` for both the default and the named export. The declarations are generated with TypeScript 6 ([#62](https://github.com/CLDMV/sizeofvar/pull/62)).

### `sizeofvar-dev` export condition ([#59](https://github.com/CLDMV/sizeofvar/pull/59))

`"."` carries a `sizeofvar-dev` condition that maps `import` to `src/index.mjs` and `require` to `src/index.cjs`. Run Node with `--conditions=sizeofvar-dev` (or put it in `NODE_OPTIONS`) to load the source in a checkout. Without it, the package loads the built `dist/`, which needs `npm run build` first. Published installs only contain `dist/`, so the condition has no effect there.

## 💥 Breaking Changes

Both of these ship in a minor release, even though they can stop an existing install from working.

### Node.js 22.22.0 or later is required ([#59](https://github.com/CLDMV/sizeofvar/pull/59))

v1.0.14 declared no `engines` field and was plain CommonJS that loaded on any Node.js. v1.1.0 sets `engines.node` to `>=22.22.0`. The CommonJS entry relies on Node's `require(esm)`, which needs a recent Node.js to run without a warning, and the build and test toolchain needs a recent Node.js 22 as well. The CI and publish matrices start at 22.22.0.

On an older Node.js, npm prints an `EBADENGINE` warning on install, or refuses to install when `engine-strict` is set, and `require()` throws the `ERR_REQUIRE_ESM` error described above.

### Only the package root is exported ([#59](https://github.com/CLDMV/sizeofvar/pull/59))

v1.0.14 had no `exports` map, so `require("@cldmv/sizeofvar/sizeofvar.js")` loaded the file directly. The new map only exposes `"."` and `./package.json`, so that path, and any other deep import, now fails with `ERR_PACKAGE_PATH_NOT_EXPORTED`. Import `@cldmv/sizeofvar` instead.

## 🔒 Security & supply chain

- `overrides` pin `katex` to `>=0.19.1 <1.0.0` and `minimatch` to `^11.0.3`, which clears advisories that reach the repository through `@eslint/markdown` and ESLint ([#61](https://github.com/CLDMV/sizeofvar/pull/61)). Both are development-only. The package still has no runtime dependencies.

## 🔧 CI & tooling

- **Real build:** `build` is tsup and `build:ci` runs lint, the format check, the type declarations and the build. Both used to be `echo` placeholders. `ci.yml` uses `npm run build:ci` for the matrix and coverage jobs, and `bundle-size.yml` measures `dist/` instead of the root `*.js` file ([#59](https://github.com/CLDMV/sizeofvar/pull/59)).
- **Lint and format:** the CLDMV base ESLint and Prettier configs, a `.prettierignore` and a pre-commit hook that runs `lint` and `format:check`. The source got a one-time format pass, and five lint errors were fixed without changing behavior: unused names, an empty `if` block and a redeclared `var` ([#59](https://github.com/CLDMV/sizeofvar/pull/59)).
- **Tests:** the suite runs against `src/` with the `sizeofvar-dev` condition. A new entry test covers the ESM default and named exports, `src/index.cjs` and resolution by package name, and `npm run test:dist` builds and checks `dist/index.cjs` against `dist/index.mjs` with `node --test` ([#59](https://github.com/CLDMV/sizeofvar/pull/59)).
- `tmp/` and `dist/` are gitignored ([#58](https://github.com/CLDMV/sizeofvar/pull/58), [#59](https://github.com/CLDMV/sizeofvar/pull/59)).

## Upgrade notes

- **Node.js 22.22.0 or later is now required.** v1.0.14 ran on any Node.js. Upgrade Node.js first, or stay on v1.0.14.
- **Replace deep imports** such as `require("@cldmv/sizeofvar/sizeofvar.js")` with `require("@cldmv/sizeofvar")`.
- `require("@cldmv/sizeofvar")` and `import sizeofvar from "@cldmv/sizeofvar"` keep working as before, and return the same sizes.
- New: the named export `import { sizeofvar } from "@cldmv/sizeofvar"`, and TypeScript declarations.

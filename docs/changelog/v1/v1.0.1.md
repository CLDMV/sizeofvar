# sizeofvar v1.0.1 Changelog

**Release Date**: March 2018
**Release Type**: Patch

---

## Overview

First release of sizeofvar, published to npm as `@cldmv/sizeofvar` (an unscoped `sizeofvar` package was published and withdrawn the same day). It bundles everything from the initial import on 2018-03-01 through the scoping of the package to CLDMV.

---

## ✨ Features

- **`sizeofvar(value)`** estimates the V8 memory footprint of a value at initialization or assignment time. `sizeofvar.js` exports a single function that works out the type of the value (boolean, number, string, object, array) and returns a byte count using per-type base sizes.
- **Recursion** — objects and arrays are walked recursively; nested members are costed with their own per-type adjustments, and objects with several keys add a per-key-group overhead. Top-level values and nested values use different base sizes.
- **Numbers above 2^31** add an extra allocation, and numbers stored in arrays carry a small additional cost.
- **Memory test harness** — `test/test-mem.js` plus per-type scripts under `test/sizeofvar/` (array, bool, number, object, object-complex, object-key-length, object-string, string) compare the returned number against what Node reports. It is run with `node --expose-gc test/test-mem.js <command> [-v]`, where `-v` enables verbose output. The harness uses `yargs` (a dev dependency) for argument parsing.
- **Package** — scoped as `@cldmv/sizeofvar`, GPL-3.0, entry point `sizeofvar.js`, with a README covering install, usage and the test commands.
